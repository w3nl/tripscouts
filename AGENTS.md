# AGENTS.md: working on TripScouts

Notes for AI agents and new helpers. The README says what the game is; this file says what you cannot see straight from the code. The general recipe for a game like this is in [docs/blueprint.md](docs/blueprint.md) (in Dutch).

> **Spoilers:** the solutions of all code locks are below. You need them to test.

## What this is

A platform game in the browser (walk, jump, find things, do tasks, crack codes) called **TripScouts** (until November 2026 **Cabin Week**). **The story:** two families want to go on holiday together but can't agree where, so the player goes ahead as their **trip scout** and tries out ten trips across Europe, a week each. It started as a Christmas week in a holiday cabin near the **fictional** village of **Pinebrook** (the Ardennes trip).

- **The name** is written **TripScouts** (one word; on the title screen "Trip" and "Scouts" in two colours). **The repository** is `w3nl/tripscouts` (until November 2026 `w3nl/cabin-week`; GitHub forwards the old address, but GitHub Pages without the custom domain does not: that would move from `w3nl.github.io/cabin-week` to `w3nl.github.io/tripscouts`). **Internal names keep the old name on purpose,** so nothing breaks: the Android package `nl.w3nl.cabinweek` (can never change), the save data (`localStorage['cabin-week']` and `cabin-week-*`, or players lose their progress), the service worker cache prefix `cabinweek-`, the signing key alias `cabinweek`, and the artifact and file names of the Android build (`cabin-week.aab`, `cabin-week-google-play`). Use TripScouts in everything players or stores see.
- **Source and licence:** like the escape rooms, the title screen links to the source code and the licence (`#credits` in the version line: *Source code · Licence (GPL-3.0)*, Dutch *Broncode · Licentie (GPL-3.0)*), and a comment at the top of `index.html` says the same. In the Android app links that open a new window go nowhere, so there `app.js` shows them as plain text (`github.com/w3nl/tripscouts · GPL-3.0`). **The privacy policy link** (*Privacy policy* / *Privacybeleid*, next to them) is a normal link to the bundled `privacy.html` in the same window, so it also works in the Android app, the Linux app and the Chrome extension (Google Play wants the policy inside the app too). On the Android Back button, `MainActivity` goes back to the game from there instead of closing the app.
- **The story in the game:** the tagline under the title ("Two families, ten trips. You scout where they go!"), "days to scout" and "days scouted" in the countdown box, "Trip scouted!" when a trip is done, "Scouting: <trip>" on every intro card, "Choose a trip to scout" on the map, and on the last card of a trip a **scout's verdict** (`verdict` in `REGIONS`: stars and one funny line) plus how many of the ten trips you have scouted.

- **The Hills:** Paul and Laura with Sophie and Lily. **The Woods:** Rob and Anna with Finn, Tom and Max. **Laura and Anna are sisters.** Lily and Tom are in the same class. 4 adults and 5 kids. You choose one of the nine, or **make your own hero** (the tenth tile, "+ Your hero"); you meet the others in the levels.
- **Regions:** ten trips (five in winter, Dalmatia, Småland, Scotland, the Ardèche and the Veneto in summer), chosen on a **map of Europe** (the 🗺️ button on the title screen): the **Ardennes** (the original week near Pinebrook), the **North Pole** (Santa's village), **Tirol** (a ski week in the fictional village of Lindenalm), **Norway** (a red cabin by the fjord near the fictional village of Fjordvik), the **Netherlands** (a little house by a windmill near the fictional village of Tulpendam), **Dalmatia** in **summer** (the fictional Camp Lavanda on the Croatian coast), **Småland** in **summer** (a red cottage by a lake near the fictional village of Lingonby, Sweden), **Scotland** in **summer** (the fictional Highland village of Glen Rowan), the **Ardèche** in **summer** (the fictional Camping Les Cigales near the fictional village of Roquelune, France), and the **Veneto** in **summer** (the fictional Camping Laguna near the fictional village of Portoverde, Italy). Each region is its own week of **eight days, one level a day**, with its own progress: you can start any region at day 1. More places are on the map as grey dots (Iceland, Tuscany, Catalonia and Greece: "coming later", not built yet; the ideas are in [docs/ideas.md](docs/ideas.md)).
- A day unlocks when you finish the day before. **There are no dates and no countdown**: the title screen shows your progress in the region (`8 winter days to scout`, `3/8 days scouted`, `🏆 Trip scouted!`).
- **English (en-GB) by default, Dutch (nl-NL) as an option** (see "Languages").
- **Plain HTML, CSS and JavaScript with canvas. No build, no framework, no runtime dependencies** (the two fonts, Fredoka and Nunito, are in `fonts/`: nothing is loaded from other servers, see [fonts/README.md](fonts/README.md)). All graphics are drawn in code; there are no images except the app icons.
- Static site at **https://tripscouts.online/** (GitHub Pages, see [docs/domain.md](docs/domain.md); cabinweek.online redirects there), installable as an app, playable offline. Also works as a loose file (`file://`), but then without app and offline.
- A **Linux app** (a snap for the Snap Store, `linux/`, see [docs/linux.md](docs/linux.md)), with the same game files as the website.
- One Android app for phones, tablets and Google TV (`android-tv/`, package `nl.w3nl.cabinweek`; the folder, the workflow file `google-tv.yml` and the release tag `google-tv` keep the old TV name on purpose, because links and tools use them). Google Play Games on PC is optional and not turned on.
- **Snapcraft source builds:** root `snapcraft.yaml` builds the existing Electron app for amd64 on core22 with the GNOME extension, using Node 26 and `1.<GAME_VERSION>.0`. It includes `linux/tripscouts.desktop` and the app icon. The existing GitHub electron-builder snap workflow remains on core20; choose one store publishing route to avoid duplicate revisions. See `docs/linux.md`.
- **Chromebooks (Chrome OS):** three routes, documented in `docs/chromebook.md`: install the existing PWA from Chrome, install the Chrome Web Store extension, or install the same Android bundle on a Google Play-enabled Chromebook. No separate Chrome OS build. The Android manifest keeps touchscreen/TV/gamepad features optional, declares `android.hardware.type.pc` optional for native mouse/touchpad input, and explicitly enables activity resizing. Its existing `configChanges` keeps the WebView alive on window resizing. Play Console device eligibility and real Chromebook testing still need checking; Google Play Games on PC is Windows, not Chrome OS.
- `package.json` and `node_modules/` are only for the tests, the local server and the tools.

### No personal information

TripScouts is a public version of a game that was made for one family. **Keep it fictional:** no real surnames, no real village or address, no dates or countdown, no birth years, nothing about anyone who passed away. The tests check for a hashed list of words from the original (`tests/titel.spec.js`). Real *places* that anyone visits are fine (the Ardennes as a region, Luxembourg's Christmas market, Innsbruck, the North Pole), and so are the Lego and the Saabs. Villages where the families stay are fictional (Pinebrook, Lindenalm, Fjordvik, Tulpendam, Camp Lavanda, Lingonby, Glen Rowan, Roquelune, Camping Les Cigales, Portoverde and Camping Laguna).

### Special days

- **Day 3, the Christmas market in Luxembourg**, is a quiet day (`quiet`): something to find, a task and a code lock, but no enemies, spikes or pits, no confetti and no joke when you finish. In the church you can light a candle ("You light a candle."); it is optional, gives nothing and names **no one**. Keep this day calm.
- **Day 4 is Paul's birthday** (he turns **40**), at the cabin, **with Lego**: the collectables are Lego bricks, on level 2 there is a Lego build with "40" and a Saab made of Lego, and the spikes are Lego bricks on the floor. Paul wears a party hat in that level (`birthday: "Paul"`).
- **Saabs:** Paul drives a **Saab 9-3 SportCombi in silver with a roof box** (on arrival, and on the drive home next to a dark estate car). On Christmas Day there is a **red Saab 900 three-door with a Christmas tree on the roof**. In Luxembourg a **Saab 96** is parked. Indoors (theme `huis`) Paul wears a **green Christmas jumper with a Saab 900**. Never draw number plates.
- **Days 5 and 6** are Christmas Day and Boxing Day.

## Languages

- **English is British English (en-GB)**, like the Google Play listing: colour, favourite, harbour, jumper, lorry, rowing boat, chips (not fries), sledge. **Dutch is nl-NL.** Regions may use a few local words where they fit, explained by context: in Scotland *wee*, *aye*, *bonnie*, *braw*, *dreich*, *haar*, *midgies*, *Haste ye back!*; in the Ardèche *bonjour*, *merci*, *au revoir*, *s'il vous plaît*, *oh là là*; in the Veneto *ciao*, *grazie (mille)*, *arrivederci*, *gelato*, *vaporetto*, *acqua alta*, *enrosadira* (in the Dutch text with a short explanation in brackets).
- **Every text in the game is written as `T("English", "Nederlands")`.** `T` picks one when the scripts load, so level data, jokes and names of things are plain strings afterwards. Never write a bare string the player sees.
- **`index.html`** has the English text in the page and the Dutch in `data-nl` (innerHTML), `data-nl-label` (aria-label), `data-nl-title` (title) and `data-nl-content` (meta). `js/i18n.js` swaps them when `LANG === "nl"`.
- **Choosing:** the buttons *English* / *Nederlands* at the bottom of the title screen call `setLang()`, which saves the choice in `localStorage['cabin-week-lang']` and reloads. `?lang=nl` or `?lang=en` in the link also works and is remembered. Default: English.
- Dutch texts are usually longer: check the menu on 960×540 in Dutch (`tests/telefoon.spec.js` does that).

## How it fits together

- **Plain scripts in one shared scope**, loaded by `index.html` in this order: `i18n`, `data`, `levels`, `levelgen`, `region-pole`, `region-tirol`, `region-norway`, `region-netherlands`, `region-dalmatia`, `region-smaland`, `region-scotland`, `region-ardeche`, `region-veneto`, `core`, `regions`, `canvas`, `sprites`, `game`, `world`, `screens`, `hero`, `transfer`, `voice`, `ambience`, `gamepad`, `app`. Every top-level name must be unique across all files.
- **Order matters while loading.** Functions are only hoisted within their own file, and `const`/`let` only exist after their line. Code that runs while loading (like `genLevel()` in `levelgen.js`) may only use things from earlier files. That is why `rng()` is in `data.js` and `T()` in `i18n.js`.
- **One drawing context `g`** (a `let`). `withCtx(ctx, fn)` swaps it to another canvas for a moment, so the same drawing functions also draw textures, background layers and portraits.
- **The world is a grid** of 15 rows of 32 px; the screen always shows all 15 rows and scales (`scale`). Characters in `L.grid`: `#` ground, `=` platform (only from above), `S` block, `^` spikes (brambles, Lego bricks, icicles, sea urchins, thistles, stalagmites), `G` task gate, `H` code door, `|` ladder, `R` a rock in the river (solid, drawn by `drawRock()`). Row 12 is the normal ground; you stand on row 11.
- **A fixed time step** of 1/60 s (`step()` in a loop in `app.js`), drawn with interpolation (`renderSmooth()`), so walking is smooth on a 50 Hz TV too. `render()` must not change `P.x`, `cam` or enemy positions. One-shot keys (jump, talk) go through `edges`; held keys through `held` (keyboard and touch), `padHeld` (controller) and `tvHeld` (controller in the Android app). Keyboard, remote and the TV app pass the moment of pressing and releasing (`queueHold()`, `applyHolds(simT)`), so a short tap is a short step even on a busy device. A waiting release only holds up its own key (never ← or → after it), never waits more than a second, and `eventTime()` treats a timestamp that is far off or in the future (some Android/TV WebViews use another clock) as "now": otherwise walking could hang at the start of a level and then jump many steps at once (`tests/besturing.spec.js`).
- **The wide menu** (`html.wide`, `fitMenu()` in `canvas.js`): on a screen wider than tall, the title screen has two columns and scales with `--fit` from a 960×540 design, so nothing scrolls. Adding something to the title screen? Check 960×540, 1366×768 and 740×360, in Dutch too.
- **Menus with keyboard, remote and controller:** arrows choose the nearest button, Enter/OK/✕/A presses, Back/○/B goes back (`tvBack()`). The title screen includes visible install-bar buttons and links in navigation. Until mouse or touch is used, focus is on a button right away (`menuAutoFocus()`).
- **Physics** (in `step()`): gravity 0.55 (1.1 when jump is released while rising), jump −11.6, max. 4.4 px per step sideways, smooth acceleration on the ground (0.12 rising to 0.7). **Running** (Shift/Ctrl, L1/R1/L2/R2, or double-tap and hold) raises the top speed to 6.2. Coyote time 7 steps, jump buffer 8 steps. You jump just over **3 tiles up** and **4 tiles across**. **Belly slide** (`P.slide`): walking plus ↓/E/□/○/💬 with nothing to talk to: you shoot ahead and slide (furthest in the snow); sliding knocks over animals, but spikes, pits and bumping still count. **Dropping through a plank:** ↓ (or E/💬/□/○) while standing still on a plank (`=`, not the ground) drops you through it (`P.drop`: for 14 steps planks don't catch you; `onPlank()`). **Ladders** (`|` in the grid, `P.climb`): hold ↑ (or jump) at a ladder to climb up, ↓ to climb down, also from the plank at its top; no gravity while climbing, you can step off sideways. `held.down` and `padHeld.down` carry ↓. `tests/besturing.spec.js` guards this; if you change the physics, check every level.
- **Regions** (`js/regions.js`): `LEVELS` and `WEEK` always hold the days of the active region; `setRegion()` swaps their contents, so the rest of the game keeps using `LEVELS[i]`. The map (`#mapWrap`, state `"map"`) draws Europe as an SVG from hand-simplified coastlines (`COASTS`, longitude/latitude, projected flat with `mapXY()`), with a button (`.pin`) per region; in landscape the map is on the left and the text on the right. Arrows, Enter, Back and the controller work there like in every menu (`gpRoot()`/`gpDefault()` in `gamepad.js`). Adding a region: a `region-….js` with eight `genLevel()` levels, an entry in `REGIONS` (with a `week` and a `finale`), the file in `index.html` and `CORE`, a `FLAGS` entry for its checkpoint flag in `world.js`, and the region in the loop in `tests/dagen.spec.js`.
- **Region gameplay:** every region plays differently, not only looks different. Options on a level (read by `genLevel()`, `step()` and `render()`):
  - `hills: [low, high]`: the ground goes up and down between those rows (12 is normal, 9 is high), at most 2 rows at a time so you can always jump it. Everything in a piece of the level is placed relative to the ground there; the start, the gate and the code door are on flat ground. Tirol climbs like a mountain; Norway has cliffs.
  - `movers: "floe" | "gondola" | "boat"`: a gap of 7 tiles (too wide to jump) with an ice floe, a cable-car gondola or a rowing boat that goes back and forth (`L.movers`, waiting at each end) and carries you (`P.mover`). Stand on it like on a plank. A **gondola rides a slanted cable**: up the mountain (2 or 3 rows, the ground on the far side is that much higher) or down where the ground is already high (`rise` on the mover; `y0`/`y1`, and `dy` moves you along), with a station post at each end. Floes and boats stay level. The reachability test in `tests/dagen.spec.js` counts its whole track as standable.
  - `islands: n` with `movers: "boat"` (the Veneto: Venice, Murano and Burano, the lagoon): `n` boat crossings spread over the level instead of one, so you hop from island to island. `boatLook: "vaporetto"` draws the boats as Venice's water bus (same physics as a boat). Without `islands` a level has one crossing, as before.
  - `river: { len }` (the Ardèche, day 2): a stretch of river near the start to canoe down, `len` tiles long (the level gets that much longer). The generator steps the bank up to row 10, so the river can drop down **two small waterfalls** (10 → 11 → 12; `L.d.river.surf` has the water row per column), each followed by **rapids** (`rapids`), puts **rocks** in the water (`rocks`, cells `R`: low ones and tall ones, never next to a waterfall or a bank; spread as on a river of 60 tiles, so a longer river has more water between the rocks, not more rocks) with peaches in an arc above them, floats one of the three things above the river, and puts a sign at the start, a flag after the far bank and canoes on both banks (`canoe` decoration). In the game (`inRiver()`, `waterTop()`, `riverCurrent()` in `game.js`) you sit in a canoe (`P.canoe`, drawn by `drawCanoe()`; the paddler is clipped at the edge of the canoe, so no legs show under it, also mid-jump), the current carries you along (1.1 px per step, 2.3 in the rapids), also while you jump; standing on a rock it doesn't. Jump over the rocks (hold jump for a tall rock): paddle or drift into one and you **capsize** (`capsize()`, `P.capsize`: "Capsized!", the canoe floats upside down for a moment, then, like after a fall into a pit, a heart less and back to the last flag). You land on the water only from above, so you go down a waterfall with a splash but can't paddle back up. The reachability test counts the river at its own height. `drawWater()` draws each stretch at its own height, with the waterfalls and the foam of the rapids.
  - `ride: { kind, len }`: a stretch near the start, `len` tiles long, where you don't walk but **ride**: `ski` (Tirol day 2) and `sled` (Tirol day 5) go down a slope, while `skates` (the Netherlands day 5), `bike` (the Netherlands day 6), `kicksled` (Norway day 2) and `railbike` (Ardennes day 2) are flat. Most rides have small blocks and tall rocks: a block stops you without harm, but hitting a rock costs a heart and sends you back to the last flag. On the Hoge Veluwe the longer bike ride mixes blocks, rocks and branches, spaced 12–19 tiles apart. On both bikes hold ↓ or 💬 (controller: down or X/B/Y) to duck under branches. Their order and spacing vary, and branches have two heights: small riders can fit under some without ducking. Some branches have a tall visible `canopy` (`RAIL_CANOPY_HEIGHT`), which cannot be jumped over. `bikeRiderBounds()` follows the drawn rider's size and pose, including jumps, to decide whether they hit a branch. The rail bike stays on its rails: jump above low ribbons. Cattle grids at both ends keep animals off the entire track and leave room for the rider to get on and off safely; animals chasing you wait at a grid, others turn around. `P.railJump` is the rider's height above the bike, not the height of the bike, and both rail hazards cost a heart and send you back to the flag just before the ride. The other map pieces and task item remain outside the rail ride. `P.ride` (`rideAt()`) swaps walking for `RIDE_FEEL` in `game.js`, with different acceleration, braking and coasting for each ride. No belly slide on a ride. `world.js` draws the vehicles; `rideSeat()` places and clips seated riders, and the rail bike and pedalling legs scale with the rider. The rail bike's normal legs are hidden while seated and return during jumps. On both bikes, `drawPerson()` reaches for the grip (`BIKE_GRIP` / `RAILBIKE_GRIP`), including while ducking; jumping off the rail bike releases the handlebars. Ducking rotates the body at the hip without squashing it, keeping the head upright. A new kind needs a `RIDE_FEEL`, a `RIDE_SIGNS` entry and a drawing (`tests/besturing.spec.js`).
  - **Husky sledge** (Norway day 3): a 120-tile ride with two running huskies pulling a standing sledge. ←/→ steer in either direction and jump lifts the whole team over the snowbanks. The lead dog's nose (`HUSKY_LEAD`) stops at a snowbank without losing a heart. `drawHuskySled()` draws the dogs, harness and sledge; the rider's hands reach the handle. The dogs' steps follow distance travelled, so they stop when the sledge stops.
  - **Ride crashes:** hitting a tall rock on a bike, skis, skates, sledge or kicksled, or a branch or ribbon on a bike, sets `P.rideCrash` for 45 steps. The rider sits on the ground; the bike has a bent front wheel, or the sledge lies upside down. The kicksled stands beside the rider. Input is ignored until the heart is deducted and `respawn()` returns the rider to the last flag. The canoe uses its own `P.capsize` animation.
  - `ice: true`: slow to get going, slow to turn, and you keep sliding when you let go (North Pole, the toboggan run, the kicksled).
  - `water: true`: the gaps are water (North Pole, Norway), drawn by `drawWater()`.
  - `dark: { r, key, quest }`: darkness with a circle of light around you of radius `r`, bigger for every thing you find (`key`) and once you have the task item (`quest`). The northern lights night at the North Pole (lanterns), the troll forest in Norway (the torch) and the Chauvet Cave in the Ardèche (cave lamps). `drawDark()` draws a dark layer with holes of light (`darkLights()`): one around you, and one around every lamp or torch you lit (`LAMP_LIGHT`, about 3.6 tiles, with a warm glow), which stays light when you walk on. The layer is drawn at half size on its own canvas (`DARK_CV`) and scaled up, fast enough for the TV.
  - `wind: n`: gusts that push you (`windNow()`: mostly against you, sometimes from behind; `n` is the strength, about .35 to .7), less in the air than on the ground, shown as white streaks (`drawWind()`). The Netherlands.
  - `weather: true` (Scotland): changeable weather, about ten seconds each of sun, a breeze (white streaks) and a shower (rain and a slightly greyer screen), by `L.time` (`weatherPhase()`, `drawWeather()`, drawn in front of the world like the wind). Only to look at: unlike `wind`, it never pushes you.
  - `summer: true` (Dalmatia, Småland, Scotland, the Ardèche, the Veneto; in the `bos` theme butterflies fly instead of autumn leaves): no snow anywhere, summer clothes (`drawPerson(..., { summer: true })`: a light T-shirt instead of the coat, shorts, no hat or scarf), "summer days" on the title screen, turquoise water, and no snow on the title background.
  - `swim: true` (Dalmatia, where the sea is warm, the lakes of Småland, and the river in the Ardèche): in the water of a gap you float (`P.swim`, the surface is `SWIM_Y`) instead of falling, and you can jump out again (`P.swimPrev`: the gentle bobbing never counts as leaving the water, so a jump out always works). The reachability test counts the water as standable. Where `swim` is off, water is still deadly (Norway, the North Pole, Plitvice: no swimming in the national park).
  - `moose: [fractions]` (Småland): a moose (`alg`, 56×50) walks slowly on flat ground. It can't be knocked over: land on its back and you bounce up high (vy −15.5, about 6 tiles); bump into it and it gently pushes you away, without hurting you.
  - `stalls`: the names on the market stalls of a level (otherwise mulled wine, waffles, and so on).
  - `ladders: true`: up to two lofts (the `loft` piece): a plank high up with a ladder (`ladderCols`) to climb, the 3rd thing on top and coins along it; a sign near the first one explains ↑/↓. Indoor days at the North Pole (workshop, post office), the Tirolean hut and fondue night, and the Småland car meet. The reachability test counts ladder cells as standable.
  - `interior: "wood" | "workshop"`: indoor levels with pine panelling (Tirol) or red-and-white stripes (Santa's workshop and post office).

  - **The gate** (`quest` as before, or `task: { kind, hud, name, need, done, after }`, or neither for no gate): `levers` (3 levers before the gate, `L.switches`), `lights` (3 lamps, or torches with `look: "torch"`; in a dark level each lit lamp makes the light bigger, `dark.lamp`), `timer` (ring the bell `L.bell` well before the gate; the gate stays open `secs` seconds, then closes again unless you are through or standing in it; while it is open, `drawGateTimer()` shows a countdown at the top of the screen with a bar and an arrow to the gate, red and pulsing in the last two seconds, when the ticks also go faster), `follow` (a lost animal `L.animal`, drawn as the emoji `animal`: a bit see-through while it hides; once found bigger, solid, with a white outline and drawn in front of you. Emoji take the alpha of `g.fillStyle`: set an opaque fill before `emoji()` if a see-through colour (like `shadowAt()`) came just before. Clock locks with educational signs set `code.learning: true`. Question clues and learning clock signs have room away from other interactions, so an NPC cannot block them. Talking to a clue shows its question; melody answers 1–5 select do, re, mi, sol or la. Existing locks without questions retain their original behaviour.
- **Regional animals:** enemies and scenery belong to the region. Robot vacuums, Lego bricks and the "PAUL 40" garland are only in the Ardennes cabin (`birthday`). Outdoors, `spikeKind: "thistles"` gives thistles on any theme (the Ardèche, on the `kust` limestone, where the sea urchins would not belong). At the North Pole there is only one lost penguin (day 1); otherwise arctic foxes and lemmings, with polar bears, walruses and a musk ox as scenery.

stalactites and columns; no sun or stars), `laguna` (the Venetian lagoon: flat water, marsh islands, fishermen's huts on stilts, channel poles, flamingos, Venice on the horizon), `venezia` and `burano` (the lagoon with houses straight out of the water, a bell tower, domes and gondolas; The title screen shows the scene of the active region. - **Interactions** (talk, read, lantern, code lock) all go through `interact()` (E, ↓, Enter or 💬). A conversation goes on with Space/E/✕/a tap, or **ends when you walk away** (`walkAway()` in `game.js`: a new press of ← or →, on any device; if you were still holding one when it opened, let go first): the balloon closes, its callback still runs (a gate that opens), and you walk on in the same step. - **Walking animals** (`drawEnemy()`): legs swing from the hip with `walkLeg()`, four-legged animals trot with `trotLegs()` (diagonal pairs together) and the body bobs a little (`stepBob()`). The step phase comes from the distance walked (`e.x`), so the legs stop when the animal stops. Scenery animals (`BG_ANIMALS` = `BG_KINDS` in `levelgen.js`: cows, polar bears, walruses, musk oxen, deer, moose, the flamingos of the Veneto) stand still **in the landscape**, on a background layer, and move exactly with it (`drawBgAnimals()`, `bgAnimalAt()`): usually the middle layer with the villages (parallax .3, `BG_SIZE` .42; each layer remembers its first ridge as `_ground`, a layer without one like the lagoon gets a flat ground), and where the near layer is a dense forest (`BG_NEAR`: snow, the Alps, the fjord) the near layer, on the snow between its trees and the path (parallax .5). `drawBackground()` calls it right after that layer, so nearer layers and the path cover them; `drawDeco()` skips them in the world pass. The generator only places them where the path is at row 12 (`fits()`), so the ground behind the path is in view. Their feet stay on their layer's ground, only lifted to `BG_CLEAR` above the normal path line where that ground runs lower (the near layers); where the path is higher (hills), the path covers them, they are never pushed up into the air. A layer can set its animals' ground itself (`LAYER_GROUND`): the Dolomites have an alpine meadow in front of the forest, where the cows graze. They are never left out: some `count` locks count them (cows, elks, chamois, reindeer). Animals you can bump into (enemies, the penguin, the moose `alg`) stay on the path. The cow (`cow`) is a Holstein in the Netherlands (now and then a red-and-white one) and a brown Alpine cow with a bell in the Dolomites (`scene: "dolomiti"`); the polar bear (`polarbear`) has a high rump, a long neck and a Roman nose. Their patches and shading are clipped to the body.
- **Background layers never float:** every layer reaches down behind the layer in front of it (the far mountains of the Dolomites run down to a base of scree and forest below the top of the meadows), so there is never sky between two layers.
- **No seams:** the screen scales (e.g. ×1.35), so the edges of things drawn per tile fall on half pixels and the background shines through as thin lines that flicker while the camera moves. Tiles therefore overlap the next one by one screen pixel (`tile()`), the tile atlas copies every tile's edge one pixel outwards, and water is drawn as one rectangle per stretch (`drawWater()`). In front of a swimmer the water is drawn again in the same colour, see-through, so there is no box around them.
- **Fast enough for the TV:** layers drawn once per theme and only the band that has content (`layerBand()`), tiles from one atlas per theme, reused gradients (`grad()`), emoji cached as images (`EMOJI_CACHE`), an opaque canvas. Reset a translated context with `setTransform()`.

### State and saving

- Saved in `localStorage['cabin-week']`: `{ unlocked, char, best, region, regions }`. `unlocked` and `best` are the progress of the **Ardennes** (so older saves keep working); the other regions are in `regions[id] = { unlocked, best }` (`prog(id)` gives the right one). `region` is the region chosen on the map. `char` is 0–8 (one of the nine) or `"me"` (your own hero); `hero` holds the choices of your own hero (`{ name, size, voice, skin, hair, hairCol, extra, extraCol, coat, coatCol, legs, pants, glasses, beanie, scarf }`; older saves without `legs`/`extra` get the defaults: trousers, nothing in the hair). Use `heroChar()` for the character you play with, never `CHARS[save.char]`. A day counts as **done** when it has a `best` entry. The language is in `localStorage['cabin-week-lang']`. Every access is in `try/catch`; without storage the game still works (`tests/voortgang.spec.js`). The days and your own hero move to another device with a progress code and a hero code (`js/transfer.js`); if you add something to the save, add it to `cleanProgress()` or `cleanHero()` too, or it gets lost on the way.
- Progress inside a level is not saved: a level takes a few minutes.
- The service worker cache is `cabinweek-vN`; it only removes its own old caches (`cabinweek-`).

## Tone and writing

- **Funny and warm.** Jokes about the cabin, the wifi, the bathroom rota, Uno, gourmet and raclette, chips (fries) and chocolate. Never mean about a person.

## Pitfalls (lessons learned)

Everything in "Lessons learned" in [docs/blueprint.md](docs/blueprint.md) applies. In particular:

- `[hidden] { display: none !important; }` in `css/game.css` must stay: the top bar and the dialogue use `display: flex`.
- **A key that opens a window is only handled in the next `step()`.** In tests: wait until the window is visible.
- **`page.goto` to the same page with only a different `#` does not reload.** Use `seed()` (which reloads) or the Menu button.
- **Levels must be reachable with the real jumps:** max. 3 tiles up, 4 tiles across. `tests/dagen.spec.js` checks every level with a search and plays every day.
- **Gates and code doors go up to row 2**, so you cannot jump over them. No platforms right in front of a gate.
- **No `alert/confirm/prompt`.** Buttons have `type="button"`.
- **Raise `CACHE` in `sw.js` and `GAME_VERSION` in `js/app.js` together** on every change to the game, and put new files in `CORE` and `index.html` (a test checks this).
- **Hints** (`updateHints()` in `app.js`): the install bar only on the title screen (Android: web app or the app on Google Play `https://play.google.com/store/apps/details?id=nl.w3nl.cabinweek`; Chrome: Chrome Web Store extension and, when available, the web-app install prompt; iPhone/iPad: Share → Add to Home Screen), not when running as an app or in the TV app; *Not now* hides it for 14 days (`localStorage['cabin-week-install-later']`). The rotate hint only on a touch screen in portrait.
- **iPhone and iPad (Safari):** sound starts after a tap (`unlockAudio()`); `-webkit-text-size-adjust: 100%` must stay; the `apple-mobile-web-app-*` meta tags give full screen from the home screen. Test with the Playwright iPhone/iPad sizes in Chromium.
- Emoji look different per system. Use them for small things; draw important things yourself.

## Checklists

## Workflow

**Never push directly to `main`.** Every change goes through a branch from the latest `origin/main` and a pull request; the owner reviews and merges. The workflows only run when they are needed (`paths` and `paths-ignore` in `.github/workflows/`): *Play the game* runs all tests when something in the game or the tests changes (not for docs, Markdown, the Android app or the other workflows only), *Build the Android app* when the app or the game inside it changes, and *Publish the game* publishes `main` to GitHub Pages when something on the site changes (the files in `tools/build-site.js`). Add a new file or folder to the game? Check that these filters still cover it. No branch protection requires these checks, so a skipped workflow does not block a merge; if you make one required, a skipped workflow would keep the PR waiting. The review and playtest agents run on demand: the label `agent-review` or `agent-speeltest` on a pull request, or Actions → Run workflow. Ideas can be refined and built by the AI agents via the issue form *Idea*: see [docs/agent-workflow.md](docs/agent-workflow.md).
